# Oil UI · GitSSS 项目适配

项目级安装；只影响本仓库的设计协作，不是应用运行时插件。
来源与文件校验见 [SOURCE.json](SOURCE.json)，上游原始入口保留在
[UPSTREAM.md](UPSTREAM.md)。先读根目录 `AGENTS.md`，再读
[项目架构与设计约束](references/gitsss.md)。

## 目标与范围

设计北极星：**紧凑、清晰、可追踪的桌面研发工作区；用户看清对象、状态与下一步。**
保留 GitSSS 品牌和已确定的 GitHub 式工作台方向，围绕真实任务提升使用体验。
适配现有 Go 模板、TypeScript、CSS、Fomantic、Vue 和局部 React 入口。
UI 优化在目标页面原有层实现；技术栈迁移另行立项。

- 局部样式调整：只看改动处与相邻区域，不启动整站重设计。
- 存量页面精修：先保留基线，定位层级、可读性、冗余、空间利用与操作反馈问题，从共享源头修正。
- 新页面或大改版：先明确用户任务和主要动作；沿已确认方向推进。方向确实未定且会影响业务决策时才询问。
- 用户只要求安装、写方案或评审：交付对应产物，不把它当成修改业务功能、批量重做或部署的授权。

## 实施与证据

1. 只读取目标页面、相邻组件、主题变量和相关行为文档，写清主动作、当前问题、关键状态与完成条件。
2. 从实际入口取得基线；先完成一条有代表性的流程，再扩展受影响的共享页面。
3. 复用现有组件、主题 token、图标、i18n 与初始化约定；保持原字段、URL、权限、CSRF 和渐进增强行为。
4. 动效表达反馈和连续性；优先 CSS/WAAPI，通常 120–240 ms，只动 transform/opacity。
   支持减少动态效果与后台暂停，不给高频列表增加持续循环，不用动画延迟提交或掩盖等待。
5. 实际查看受影响状态：默认、悬停、键盘焦点、加载、空、失败、成功与禁用。
   保存操作验证读回；失败保留输入；名称、多行消息和百分比等信息不因精简而丢失。
6. 按任务授权和风险执行检查。只安装/编辑说明不启动服务、数据库或全量构建；
   产品改动按项目任务验证；构建与嵌入资源未核对不能视为已部署。

桌面以 1366、1600、1920 宽度及明暗主题为主要检查范围；关键区域检查 100%/200% 缩放。
窄窗口可用性不等于另做移动端。截图需实际打开看过；静态代码检查不等于视觉或业务验收。
独立评审按用户/宿主允许的协作方式进行，不能独立评审时如实标明自检。

设计说明与不含私密信息的证据放 `output/ui-review/<任务名>/`（已忽略）或仓库外临时目录；
需要共享的长期行为说明更新 `docs/` Markdown 与 `docs/site/` HTML。
报告只说明实际改动、实际证据与剩余边界，不给没有看过的画面打分。

## 本地协作边界

仅使用已授权、可用的工具和服务。安装不运行上游更新检查、付费推荐、素材下载或服务注册；
固定上游版本，更新由显式任务触发。上游脚本与资产仅供开发使用，不加入 GitSSS 前端依赖或发布包。
无需安装 DeepSeek Harness，也无需调用它的插件接口。
