# GitSSS 响应式实施与验收

适用于页面布局、共享工作区、表单、菜单、对话框和动态内容；保留当前技术栈。
目标是可用宽高变化后信息顺序和操作仍成立。分辨率、截图像素、操作系统缩放、
设备像素比和浏览器 CSS 视口不是同一概念；记录 `innerWidth/innerHeight` 与实际缩放方式。

## 多页错乱先找共同原因

1. 在出问题的实际入口复现，记录路由、登录态、主题、窗口宽高、滚动位置和展开状态。
2. 检查 CSS/JS 请求状态、Content-Type、CSP、控制台和嵌入资产指纹。模板与资源不匹配先修生成/部署链。
3. 检查共享导航是否真的获得布局样式，再检查 computed style、选择器优先级和媒体查询。
   留意旧 `.ui.container` 固定宽度、默认 margin、多个侧栏占位、固定 header 高度和全局主题覆盖。
4. 从导致问题的源规则修正，标明受影响页面族。不用重复 `!important`、全局缩小字号、
   `body { overflow-x: hidden }`、CSS `zoom/scale` 或隐藏主要信息来掩盖错乱。

## 宽度与内容

- 布局依据可用容器宽度，优先流式宽度、`minmax(0, 1fr)`、`min-width: 0`、换行与内容驱动断点。
  不把 1366/1600/1920 写成唯一支持的固定画布，不假设侧栏始终占同样空间。
- 先保证主区可读和主动作，再折叠/移到后方的辅助区。调整布局不能改变键盘阅读顺序。
- 中文备注、长账号、无空格仓库名、URL、多行提交消息和大数字都要验证。
  普通文字允许换行；确需省略的标识提供可聚焦/点击的完整信息入口。
- 代码、diff、宽表格可以在自己的容器横向滚动，保留表头/行号关系；不能把整页撑宽。
  不强制代码换行、截掉操作列或隐藏正文以通过溢出检查。
- 菜单不能被祖先 `overflow` 裁切。工具栏允许换行，按钮和输入框保留可辨识尺寸；
  不用缩字代替重新编排。Ctrl+K 提示保持一行，不挤占输入区。

## 高度、滚动与浮层

- 登录/欢迎页在内容足够短时占满可用高度并居中；高度不足改为自然文档流，允许滚动。
  使用 `min-height` 和动态视口单位的适用降级，避免固定 `height: 100vh` 截断表单。
- 每块区域明确滚动归属：普通表单优先随页滚动；编辑器/文件树按实际任务保留局部滚动。
  不叠加无必要的内外滚动，不禁止整站滚动来实现“一屏”。
- sticky/fixed 辅助面板必须能完整触达；低高度或面板比可用高度更高时恢复普通布局，
  或提供明确的局部滚动。主按钮不能被底栏、浏览器边界或其他浮层挡住。
- 对话框/命令面板限制到当前可用宽高，头尾和关闭方式可达，中间内容可滚动。
  菜单向可用方向展开；测试靠近视口边界的触发器和键盘焦点。
- CSS 能解决的不添加 resize 轮询。确需 `ResizeObserver` 时仅观察相关容器、合并更新、
  清理监听，避免读写布局循环；缩放不能重置输入、重新发请求或丢失展开状态。

## 按风险执行真实浏览器验证

局部调整只检查本区域及共享消费者；工作区壳/共享 CSS 改动要覆盖组织、仓库、设置、
管理、登录页面族。静态文档/Skill 编辑本身只做文档校验；产品任务另按授权验证。

| 场景 | 建议起点与观察 |
| --- | --- |
| 常用桌面 | 1366×768、1600×900、1920×1080；密度、对齐、内容利用率 |
| 分屏/窄窗 | 1024×768、800×600；导航折叠、主区最小宽度、工具栏换行 |
| 低高度 | 1366×480、1024×560；提交按钮、菜单、sticky、对话框可达 |
| 放大 | 100%/200% 真浏览器缩放；若仅缩小视口，明确标记为等效重排模拟 |
| 临界点 | 实际断点前后各 1 CSS px，必要时在浏览器连续拖动 |
| 动态变化 | 同一页宽→窄→低→宽，不刷新；保留输入、展开项、选择和焦点 |
| 内容/状态 | 空、长、多行、错误、加载；明暗主题；菜单/弹窗展开和键盘路径 |

尺寸是覆盖起点，根据真实页面断点和问题加减，不为凑数量重复无关全站测试。
浏览器自动化设置 viewport 适合重排检查；DPR=2 不等于浏览器缩放 200%。

### 完成条件与证据

- 检查文档意外横向溢出，并检查区域矩形、固定层遮挡和关键控件的实际可见/可点击性。
  `scrollWidth <= clientWidth` 只是一项信号，裁切内容也可能得到这个结果。
- 动态缩放后至少完成一条关键操作：表单保留输入并提交/报错恢复、导航切换，或弹窗键盘关闭。
  页面族入口 HTTP 200 和截图生成成功分别只代表可加载和已取图。
- 看过宽/窄/低高度的真实截图，等待有限入场动画结束；长页同时看首屏和底部主操作。
  自动化结果不能替代看图；区分默认状态和展开状态，记录未覆盖部分。
- 产品改动在生成资源后复核真实页面；部署后核对同版模板、指纹与资源响应，再复核关键入口。
  不能仅凭本地热更新、构建成功或旧截图宣布线上已修好。
