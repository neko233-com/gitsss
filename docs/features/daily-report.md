# Daily report agent

Organization owners configure the Responses API, Feishu webhook, schedule and classifications under **Organization settings → Daily report agent**. Configuration and delivery receipts are isolated by organization ID under `APP_DATA_PATH/daily-report/organizations/<org-id>/`; credentials are never echoed. New organizations default to a disabled schedule. Only current organization members and repositories currently owned by that organization are included. Site administrators may also access organization settings.

The scheduled role filter defaults to all roles, including users without labels. Selecting roles requires at least one label and matches any selected role. Manual analysis selects any number of explicit members and/or role labels, uses their union, and includes only organization members. Manual analysis previews the result without sending Feishu cards or changing delivery receipts; it can include an explicitly selected member regardless of scheduled account classification. No commits means no result.

Automatic delivery is disabled by default. Only accounts explicitly marked personal are eligible; unclassified, service and test accounts, and people with no attributed pushed commits are skipped. The report summarizes commits pushed since midnight in Asia/Shanghai, attributed by the commit author's registered GitSSS email. The configured provider receives commit IDs, repository IDs and commit messages; the bot receives one summary card per eligible account. Confirm that both services are approved for this data before enabling them.

When holiday skipping is enabled, weekends and configured holiday dates are skipped, except configured makeup workdays. Maintain the complete holiday and makeup-workday lists and mark each covered year. Automatic runs fail closed for a year that has not been marked as maintained. The organization owner can change the time, calendar and classifications. Manual analysis bypasses the schedule and holiday check and does not send cards.

The server checks activity records for truncation and reconstructs ordinary truncated pushes from Git when the original commit range is available. If a complete range cannot be recovered, the run fails rather than sending an incomplete report. A per-organization, per-date, per-account receipt allows a retry to skip accepted cards; a crash after Feishu accepts a card but before its receipt is saved can still cause a duplicate. Instances running this task must share the same `APP_DATA_PATH/daily-report` directory and a shared global-lock backend, or they may send duplicates. The cron monitor and server log show failures. Review the provider and webhook settings, calendar coverage, account emails and push records before retrying.

The card title shows the display name (or username), Beijing date and weekday. The model is instructed to combine each product feature into a single numbered topic with second-level bullets, describe supported product-facing functionality and improvements, and avoid implementation-level lists and unsupported claims. The model output is a summary of commit messages and can still require human review.

## Upgrade and rollback

The legacy global endpoints return HTTP 410 and the legacy scheduler no longer sends globally. They do not automatically assign a global configuration to an organization. With the service stopped, the operator may copy the old `daily-report/config.json` and `deliveries.json` into a single explicitly chosen organization's ID directory, preserving owner-only permissions and existing data; never overwrite an existing organization configuration. Copying the receipts avoids repeat delivery on the migration date. Keep the original files for rollback. Rolling back to the old binary resumes its global configuration and can resume global delivery; disable the old schedule first if that is not intended. No Git, LFS, database schema or repository migration is required.

Organization owners can configure Git author name aliases per member, one per line. A trailing `*` matches a prefix (for example `neko233*`); exact aliases take precedence over prefix aliases, and aliases take precedence over registered email. Matching ignores case. Duplicate aliases and overlapping prefixes are rejected. Only current members selected for the report can receive commits; configure `zaixiao` and `yideqing` for `tandeqing` and `neko233*` for `luohaojun` where appropriate. Existing configurations need no migration.

Organization owners can manually send a past Beijing-date report from organization settings. This uses the saved account and role filters, bypasses the schedule and calendar, includes the full selected day, and skips cards with successful delivery receipts. Future and current dates are rejected.
