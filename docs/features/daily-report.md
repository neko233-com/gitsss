# Daily report agent

Organization owners configure the Responses API, Feishu webhook, schedule and classifications under **Organization settings → Daily report agent**. Configuration and delivery receipts are isolated by organization ID under `APP_DATA_PATH/daily-report/organizations/<org-id>/`; credentials are never echoed. New organizations default to a disabled schedule. Only current organization members and repositories currently owned by that organization are included. Site administrators may also access organization settings.

The scheduled role filter defaults to all roles, including users without labels. Selecting roles requires at least one label and matches any selected role. Manual analysis selects any number of explicit members and/or role labels, uses their union, and includes only organization members. Manual analysis previews the result without sending Feishu cards or changing delivery receipts; it can include an explicitly selected member regardless of scheduled account classification. No commits means no result.

Automatic delivery is disabled by default. Only accounts explicitly marked personal are eligible; unclassified, service and test accounts, and people with no attributed pushed commits are skipped. The report covers pushes from 18:30 on the previous day (inclusive) to 18:30 on the report date (exclusive), Asia/Shanghai, attributed by author alias or registered GitSSS email. All organization schedules use 18:30 after upgrading, including existing configurations; reading them does not rewrite their files. Manual analysis before 18:30 previews the previous completed window. The configured provider receives commit IDs, repository IDs, commit messages, changed paths and source-code diff excerpts; these can contain confidential code or credentials and are not automatically redacted. The bot receives one summary card per eligible account. Approve the configured provider for this data before enabling or upgrading an active schedule.

When holiday skipping is enabled, weekends and configured holiday dates are skipped, except configured makeup workdays. Maintain the complete holiday and makeup-workday lists and mark each covered year. Automatic runs fail closed for a year that has not been marked as maintained. The organization owner can change the calendar and classifications. Manual analysis bypasses the schedule and holiday check and does not send cards.

The server checks activity records for truncation and reconstructs ordinary truncated pushes from Git when the original commit range is available. If a complete range cannot be recovered, the run fails rather than sending an incomplete report. A per-organization, per-date, per-account receipt allows a retry to skip accepted cards; a crash after Feishu accepts a card but before its receipt is saved can still cause a duplicate. Instances running this task must share the same `APP_DATA_PATH/daily-report` directory and a shared global-lock backend, or they may send duplicates. The cron monitor and server log show failures. Review the provider and webhook settings, calendar coverage, account emails and push records before retrying.

The card title shows the display name (or username), Beijing date and weekday. The model is instructed to prioritize actual changes over commit messages, group related commits by work topic and write numbered entries as `1. 【Topic】Progress. Work details`. Related client, server and test work for the same product feature stays under one topic. It may report a percentage or status only when explicitly recorded; otherwise it writes “进度未注明”. Results require human review; an example percentage is not evidence of actual progress.

Each selected commit is compared to its first parent (root commits use the empty tree); merge diffs therefore describe changes relative to the first parent. Git's diff statistics and text patch are sent as data, never instructions. Files detected as binary by Git are represented by change markers rather than decoded contents. A commit contributes at most 16 KiB of diff and each person's total diff budget is 256 KiB, divided across their commits. Truncated excerpts and discarded invalid UTF-8 are marked, and no more than 256 commits per person are accepted in one report. If a repository or commit cannot be read, the affected analysis fails instead of presenting the message as a verified change. Delivered accounts are skipped before diff collection on retry. The diff can be incomplete for large, generated, binary, or otherwise non-text changes; neither a successful run nor the model output proves complete review.

## Upgrade and rollback

The legacy global endpoints return HTTP 410 and the legacy scheduler no longer sends globally. They do not automatically assign a global configuration to an organization. With the service stopped, the operator may copy the old `daily-report/config.json` and `deliveries.json` into a single explicitly chosen organization's ID directory, preserving owner-only permissions and existing data; never overwrite an existing organization configuration. Copying the receipts avoids repeat delivery on the migration date. Keep the original files for rollback. Rolling back to the old binary resumes its global configuration and can resume global delivery; disable the old schedule first if that is not intended. No Git, LFS, database schema or repository migration is required.

Organization owners can configure Git author name aliases per member, one per line. A trailing `*` matches a prefix (for example `neko233*`); exact aliases take precedence over prefix aliases, and aliases take precedence over registered email. Matching ignores case. Duplicate aliases and overlapping prefixes are rejected. Only current members selected for the report can receive commits; configure `zaixiao` and `yideqing` for `tandeqing` and `neko233*` for `luohaojun` where appropriate. Existing configurations need no migration.

Organization owners can manually send a past Beijing-date report from organization settings. This uses the saved account and role filters, bypasses the schedule and calendar, covers 18:30 on the previous day through 18:30 on the selected date, and skips cards with successful delivery receipts. Future and current dates are rejected.

When an automatic run, historical send, or manual analysis fails, the agent sends one failure card to the organization's configured Feishu bot, including the date, execution type and delivery counts. Error details and credentials are not included; check system notices and server logs for diagnostics. If the configuration cannot be read, the webhook is missing, or Feishu itself is unreachable, the alert cannot be guaranteed and the original error remains visible in the logs or task notices. Manual validation errors and a run already holding the organization lock do not send alerts.

For the official DeepSeek API host, summary requests disable reasoning so that the bounded output budget is available for the report itself. Other Responses API providers retain their existing request format.
