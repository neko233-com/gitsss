# Daily report agent

Site administrators configure the Responses API base URL and model, API key, Feishu custom-bot webhook, Beijing daily time, and account classification at **Site administration → Daily report agent**. Credentials are not echoed after saving; a blank field retains the existing value. They and delivery receipts are stored under `APP_DATA_PATH/daily-report`, outside the source tree. Protect this directory and exclude it from public artifacts.

The role filter defaults to all roles, including users without labels, preserving existing behavior. Administrators can select specific profile labels; a user matches any selected label, and unlabeled users are skipped. The same filter applies to manual and scheduled runs. Selecting specific roles requires at least one label.

Automatic delivery is disabled by default. Only accounts explicitly marked personal are eligible; unclassified, service and test accounts, and people with no attributed pushed commits are skipped. The report summarizes commits pushed since midnight in Asia/Shanghai, attributed by the commit author's registered GitSSS email. The configured provider receives commit IDs, repository IDs and commit messages; the bot receives one summary card per eligible account. Confirm that both services are approved for this data before enabling them.

When holiday skipping is enabled, weekends and configured holiday dates are skipped, except configured makeup workdays. Maintain the complete holiday and makeup-workday lists and mark each covered year. Automatic runs fail closed for a year that has not been marked as maintained. The administrator can change the time, calendar and classifications, or trigger the current day's report manually using saved settings. Manual runs bypass the schedule and holiday check, but do not resend cards with a successful receipt.

The server checks activity records for truncation and reconstructs ordinary truncated pushes from Git when the original commit range is available. If a complete range cannot be recovered, the run fails rather than sending an incomplete report. A per-date, per-account receipt allows a retry to skip accepted cards; a crash after Feishu accepts a card but before its receipt is saved can still cause a duplicate. Instances running this task must share the same `APP_DATA_PATH/daily-report` directory and a shared global-lock backend, or they may send duplicates. The cron monitor and server log show failures. Review the provider and webhook settings, calendar coverage, account emails and push records before retrying.

The card title shows the display name (or username), Beijing date and weekday. The model is instructed to group related commits into concise numbered Chinese work topics, preserve concrete details, and avoid unsupported claims or mechanical commit-by-commit lists. The model output is a summary of commit messages and can still require human review.
