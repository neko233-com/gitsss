登录工作区

桌面登录页使用统一品牌区、清晰表单与就近错误提示。密码显隐支持键盘，只改变显示方式，不保存密码。原有用户名、密码、自动填充、验证码、记住设备、CSRF 和跳转处理保持原行为。

登录页固定展示飞书、Google、微信、Discord 和 GitHub 等常用渠道；未配置、未启用的渠道以原生禁用按钮置灰并标注“未启用”，没有授权链接。已启用渠道使用品牌图标及中文名称；仅展示层变化，不自动启用任何认证源。已有账号绑定复用同一登录表单及校验流程。有效提交后显示忙碌并防止重复提交，返回恢复。配色和减少动态效果沿用主题设置。见 实现与回滚边界。

申请凭据 → 配置回调 → 发布应用 → 绑定原账号 → 真实登录验收。

第三方渠道接入

本目录记录申请应用、配置 GitSSS、绑定账号和真实登录验收。默认保留邮箱／用户名＋密码，一个 GitSSS 账号可以同时绑定多个渠道；未配置完整或未启用的渠道不会显示登录按钮。

所有渠道通用的顺序

  1. 确定用户实际访问的站点，例如 https://git.example.com/，并固定认证源名称，例如小写 feishu。名称参与回调路径，避免上线后随意改名。
  2. 在渠道官方开发者平台创建对应应用，记录 Client ID／App ID；Secret 直接填入受保护的 GitSSS 管理表单，禁止进入 Git、工单、截图或操作日志。
  3. 进入 管理后台 → 认证源 → 添加认证源 → OAuth2，选择对应 Provider，配置名称、ID、Secret、启用状态。每个源可独立填写「登录回调站点」。
  4. 复制 GitSSS 表单显示的完整回调地址到渠道白名单。路径、大小写、协议、端口、子路径都必须一致。例如 https://git.example.com/user/oauth2/feishu/callback。
  5. 完成渠道权限、企业可用范围、测试用户、审核及发布。仅保存开发者平台草稿通常不足以让全员使用。
  6. 从回调所属的同一站点登录原 GitSSS 账号，进入 设置 → 安全 → 已关联账号绑定。随后退出，用渠道按钮重新登录，核对仍为原账号、组织和仓库权限。

企业部署保持自主注册和 OAuth 自动注册关闭。未绑定的渠道身份应进入已有账号确认／绑定流程，不能自动变成新管理员。最后一种有效登录方式不能移除；换绑应先验证新身份，成功后才替换旧绑定。

站点、Cookie 与网络

  • 优先使用有效证书的 HTTPS。HTTP 只允许在 GitSSS 回调配置中用于内网 IP、回环 IP 或 localhost；这不代表供应方也接受该地址。
  • 从 https://git.example.com/ 开始绑定，却返回 http://192.168.1.10:5030/，会丢失原站点会话。选择一个入口完成整个流程。
  • 用户浏览器必须能访问回调；GitSSS 服务器必须能访问供应方 token 和 user-info API。浏览器能打开授权页不代表服务器的外网请求也正常。
  • 认证源 CallbackURLBase 优先于 [oauth2_client] CALLBACK_URL_BASE，最后回退 [server] ROOT_URL。只改 OAuth 回调，不改变 Git／SSH／LFS remote。
  • 不在排障日志中记录 code、state、Cookie、access token、refresh token 或 Secret。仅记录脱敏错误码和时间。

验收与交接

记录应用名称、Provider、认证源名称、回调、负责人、可用范围、审核／发布状态和最近一次实际登录验收时间。不要记录 Secret。验证新增绑定、重新登录、已有密码登录、无权限账号拒绝访问、换绑、取消授权及错误回调。

关闭认证源可立即隐藏入口；已有账号与 Git 数据保留。若回滚到不识别独立回调站点的旧二进制，应先停用该源或恢复与旧 ROOT_URL 一致的回调。Secret 轮换通过供应方与 GitSSS 保护表单完成，操作前保留另一种已验证登录方式。

飞书统一登录

使用企业自建应用接入；群机器人 Webhook 不能用于登录，安装飞书桌面客户端也不会自动提供 App ID／Secret。

申请与配置

  1. 打开 飞书开发者后台，选择正确企业，创建企业自建应用，填写应用名称和说明。正式环境与测试环境建议使用不同应用。
  2. 凭证与基础信息中获取 App ID／App Secret。App ID 对应 GitSSS Client ID，App Secret 对应 Client Secret；不需要重新生成已有 Secret。
  3. 添加应用能力 → 网页应用，设置桌面端主页为实际 GitSSS 入口，例如 https://git.example.com/，保存。桌面浏览器工作流可选择新页面在浏览器中打开；暂未提供移动端时不要填写虚假的移动地址。
  4. 安全设置 → 重定向 URL，添加 GitSSS 显示的完整地址，如 https://git.example.com/user/oauth2/feishu/callback。这不是「事件与回调」中的事件订阅地址，也不是机器人 Webhook。
  5. GitSSS 添加 OAuth2 源，名称 feishu，Provider 飞书，填入 App ID／Secret 和正确的独立回调站点，启用。保持企业 OAuth 自动注册关闭。
  6. 版本管理与发布 → 创建版本，说明仅用于 GitSSS 登录；核对网页能力、所需身份信息、可用范围，保存并发布。若需企业管理员审核，审批通过才算正式可用。
  7. 用可用范围内的用户，从同一 GitSSS 入口绑定原账号，再退出进行真实飞书登录。

最小权限

当前后端调用授权、token 交换与 authen/v1/user_info，使用登录用户基本身份，不读取企业通讯录、聊天记录、群、云文档或全员邮箱。无需为登录勾选批量读取通讯录、发送消息等权限；offline_access 是持续访问授权数据，也不是基本登录必需项。只有明确需要额外敏感字段时，才按官方接口字段权限单独评审。

基本授权的身份标识是 open_id，并不保证返回员工 user_id。GitSSS 在员工 ID 缺失时使用服务器获取的 open_id；已有非空员工 ID 绑定保留兼容。不要为了修复空 ID 申请整份通讯录权限，也不要以昵称或邮箱代替稳定身份标识。

飞书首次返回、尚未绑定时，默认进入「绑定到现有账号」。企业关闭注册后不展示注册 Tab 或注册表单；原用户名／邮箱与密码验证通过后绑定，之后飞书登录回到同一账号。已经登录 GitSSS 的用户也可在安全设置直接关联。

参考：获取登录用户信息、网页登录。供应方控制台可能更新，实际字段与审批提示以当前后台为准。

内网部署与常见错误

现象 检查
没有飞书按钮 OAuth2 源已启用，Client ID 和 Secret 均非空；不是只配了通知 Webhook
redirect_uri 不匹配 完整回调白名单含正确协议、端口、路径、源名称与大小写，且没有尾部多余字符
能授权但回 GitSSS 丢失状态 开始与返回是不是同一 origin；是否从公网入口跳回内网；浏览器是否阻止 Cookie
应用不可用／无权限 草稿是否已发布、企业是否审批、用户是否在可用范围、是否选错企业身份
页面授权成功但后端失败 服务器能否访问飞书 token/user-info API；Secret 是否配错；不要把浏览器登录 Cookie 当 Secret
要求读取大量通讯录 先核对选中的是网页登录流程；当前 GitSSS 基本登录不需要这些权限
本机飞书已登录仍需扫码或确认 浏览器与桌面客户端会话并不等同；按官方授权页完成身份确认

内网回调可使用如 http://192.168.1.10:5030/user/oauth2/feishu/callback，前提是飞书控制台接受、用户浏览器可达、GitSSS 服务器能访问飞书 API。公网用户不应使用不可达的内网回调。公网回调另建匹配的配置，避免跨 origin 绑定。

验收记录模板

  • 应用名称／企业、负责人、源名称、回调地址、发布版本与可用范围（不填 Secret）。
  • 从已登录原账号绑定，记录 GitSSS 用户名；退出后飞书登录回到同一用户。
  • 原密码、SSH、公钥、组织与仓库权限仍可用。
  • 未绑定和范围外身份不得自行注册或取得权限。换绑冲突应拒绝，原身份仍有效。

微信网站扫码登录

申请

在 微信开放平台 注册并认证开发者主体，进入网站应用管理创建网站应用，按官方要求提交域名、站点信息、主体材料并完成审核。公众号、小程序、企业微信、微信支付的 AppID／Secret 不能直接替代网站应用凭据。资质、费用和域名备案要求以官方当前规则为准。

配置

  1. 审核通过后，在网站应用中获取 AppID／AppSecret。
  2. 设置应用的授权回调域，按微信后台要求填写域名；它与其他渠道填写完整 Redirect URI 的表单不同。禁止用公网不可访问的内网 IP 冒充合规域名。
  3. GitSSS 添加 OAuth2 源，名称建议 wechat，Provider 微信，填写网站应用 AppID／Secret，回调站点使用已批准的 HTTPS 域名。
  4. 核对完整回调为 https://git.example.com/user/oauth2/wechat/callback，并启用源。点击微信登录进入官方 /connect/qrconnect 页面，使用 snsapi_login 网站扫码授权。
  5. 从该 HTTPS 站点登录原 GitSSS 账号、绑定微信，再退出扫码登录，确认原用户、组织与权限。

避免踩坑

  • 微信扫码不等于短信或邮箱登录；只配置二维码图片没有身份校验能力。
  • 测试页能显示二维码，不代表网站应用审核或回调域已经正确。
  • 同一自然人在不同应用的 openid 可能不同；GitSSS 以认证源＋供应方身份绑定，不依据昵称或头像合并账号。
  • 不在前端、HTML、Git 或二维码 URL 中放 AppSecret；Secret 只用于服务器端交换。
  • 未配置或未启用的源隐藏按钮。换绑先验证新微信身份，不能占用另一 GitSSS 账号的微信。

参考：微信开放平台。审批、扫码限制与授权回调域规则以对应网站应用后台为准。

Google 账号登录

  1. 进入 Google Cloud Console，选定项目，在 Google Auth Platform 配置 Branding、Audience 和 Data Access。企业内部受众与外部受众按实际主体选择；测试模式添加被允许的测试用户。
  2. 创建 OAuth Client，应用类型选择 Web application。不是桌面应用、API key 或服务账号。
  3. 添加完整 Authorized redirect URI，例如 https://git.example.com/user/oauth2/google/callback。使用供应方认可的 HTTPS hostname 与证书；localhost 开发例外不代表任意私有 IP 的 HTTP 都能使用。
  4. GitSSS 添加 OAuth2 源，名称建议 google，Provider Google，填写 Client ID 和 Client secret。内部兼容键仍为 gplus，不要为改显示名称重写旧绑定。
  5. 填写与白名单一致的独立回调站点并启用。GitSSS 请求基本身份与邮箱，并使用 prompt=select_account：浏览器已登录 Google 也会选择账号。
  6. 登录原 GitSSS 账号后绑定，退出再用 Google 登录验证。Google 返回明确验证为真的邮箱且未被其他账号使用时，GitSSS 可加入邮箱别名，不覆盖手填主邮箱。

常见错误

现象 原因与处理
redirect_uri_mismatch 完整 URI 与 Google 白名单不一致，检查源名称、协议、端口、子路径、大小写
测试用户被拒绝 应用仍为 Testing，用户未加入测试名单，或受众选择为其他企业内部
内网 HTTP 被拒绝 配置合规 HTTPS 域名；GitSSS 允许某种回调格式不代表 Google 接受
邮箱未加入 供应方未明确验证邮箱或地址已被另一账号占用；不抢占、不覆盖主邮箱
选择了错误 Google 账号 重新发起登录选择账号；已绑定身份替换必须通过原 GitSSS 账号的安全设置

不要申请 Gmail、Drive、Calendar 等与登录无关的权限。正式发布前按 Google 控制台的受众与验证要求操作。参考：OAuth Web Server、OpenID Connect。

Discord 登录

  1. 在 Discord Developer Portal 创建应用，设置清晰名称和图标。
  2. 进入 OAuth2，获取 Client ID／Client Secret，登记完整 Redirect URI，例如 https://git.example.com/user/oauth2/discord/callback。登录不需要创建 Bot，也不需要 Bot Token。
  3. GitSSS 添加 OAuth2 源，名称建议 discord，Provider Discord，填入 Client ID／Secret 和回调站点，核对回调预览后启用。
  4. 仅请求 Provider 用于身份的基本 scope，不申请服务器管理、机器人加入服务器或读取消息等权限。
  5. 原 GitSSS 账号进入安全设置绑定；退出再进行真实 Discord 授权，核对仍是同一 GitSSS 用户与组织权限。

Discord 的通知 Webhook、Bot Token 与 OAuth Client Secret 是三种不同用途，不能混用。昵称可变，不能用昵称匹配或抢占账号。一个 Discord 身份不能同时绑定两个 GitSSS 账号；换绑与解除受到身份归属和最后登录方式保护。

如失败，先检查 Redirect URI 完全相同、源已启用、Secret 完整、应用可用以及服务器外网连通性。不要在排障截图中展示 Secret 或 access token。参考：官方 OAuth2 文档。

邮箱登录与账号邮箱

邮箱是已有 GitSSS 账号的登录标识，使用邮箱＋原密码登录，不需要申请第三方 App ID／Secret。本说明不提供邮箱验证码无密码登录。

  • 用户在账号设置修改主邮箱或管理邮箱别名。地址归属全局唯一，大小写不敏感，不能占用另一账号的地址。
  • 如站点要求邮箱确认，配置 SMTP 并完成验证后使用；SMTP 凭据不是 OAuth Client Secret，不进入公开 Git。
  • Google 已验证邮箱可作为额外别名加入，手填主邮箱保持原值。飞书／Discord 的任意字符串字段不能替代邮箱验证。
  • 企业默认关闭自主注册，管理员分配账号或按既有邀请流程操作。
  • 邮箱用于身份与提交归属，SSH 仍使用既有用户名、公钥与 Git remote。修改邮箱不改变仓库路径。

配置与安全边界见 Enterprise identities。迁移后应分别验证原用户名／密码、邮箱／密码和已绑定第三方身份，不能只验证一个登录入口就宣称全部正常。
