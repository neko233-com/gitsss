Agent 协作

人类与自动化协作者共享的工作上下文、变更规则与交接标准

权威规则

根目录 AGENTS.md 是仓库执行规则的权威来源。本页解释其工作方式，不能替代或放宽其中的要求；冲突时以 AGENTS.md 为准。

运行交接

先读取健康检查、迁移 JSON 计划、仓库 refs 与组织权限，再执行显式写入。Gitea 3000 与 GitSSS 5030 并行期间禁止自动切换端口；切换等待管理员通知。对 Actions 先读取队列和 Runner 状态；试运行关闭内置 Runner，保护现有发布流程。令牌仅从受保护文件读取，禁止进入提示词、命令参数、报告和提交。

开始工作前

  1. 读取根目录 AGENTS.md 与目标目录内更具体的 AGENTS.md（如存在）。
  2. 执行 task help，确认可用本地开发目标。
  3. 检查 git status --short --branch；保留与任务无关的已有改动。
  4. 阅读与任务相邻的实现、测试、配置和文档；不要凭旧上下文推断当前行为。

项目级 Oil UI Skill

本仓库安装了 dsh-oil-ui 附带的免费 Oil UI Skill（0.23.8），固定来源 commit 为 b67ae2df6c2c9d65e177aaa1ce703e65457b24d7。入口位于 .agents/skills/oil-ui/SKILL.md，Codex 下一轮可发现，也可显式使用 $oil-ui。仅项目级安装，不注册 DeepSeek Harness 插件或修改全局配置。

适配保留现有 Go 模板、TypeScript/CSS、Fomantic、Vue、局部 React 与双 Vite 构建入口；按目标页面的原有实现优化层级、布局、中文、配色、动效和关键状态，不迁移语言或框架。桌面工作台沿用已确认方向，使用主题 token、键盘交互和减少动态效果；Git、SSH、LFS、账号、权限与存储合同保持原规则。

适配版本 2 的 references/responsive-workspace.md 用于布局任务：按实际 CSS 视口宽高检查常用桌面、分屏、低高度、断点两侧、明暗主题和不刷新页面的往返缩放，验证输入、展开状态、菜单和主操作可达。区分浏览器真实缩放与缩小视口模拟；多页错乱先检查资产版本、加载和共享 CSS。禁止用全局裁切、缩字或固定画布掩盖问题。HTTP 200、无横向溢出和截图生成均不能单独作为视觉验收。

references/gitsss.md 映射项目架构，references/codex-tools.md 将 DSH 工具名适配到当前工具与离线 CLI。原始入口保留在 UPSTREAM.md，来源和 SHA-256 见 SOURCE.json，MIT/OFL 通知一同保留。不会自动检查更新、启动 Pro 推荐流程或把 Skill 资产加入前端包。Skill 安装本身不修改产品画面，也不需要重启服务。

设计小样、截图和走查证据放在已忽略的 output/ui-review/<任务名>/ 或仓库外私密目录；本地截图显式指定桌面尺寸。截图必须实际查看，认证和保存流程仍需真实浏览器验证。更新、移除与使用方式见 项目 UI Skill 说明；更新先在临时目录比较差异，再保留项目适配与刷新校验，禁止直接覆盖本地修改。

变更边界

可以直接做需要明确授权
任务范围内的代码、测试、文档、格式化与本地验证发布、创建 tag、推送、创建 PR、外部消息或改动生产数据
只读检查：分支、日志、配置、测试输出删除数据卷、递归删除、覆盖用户未提交文件
修复因本次改动暴露的问题扩大产品范围、改变兼容性契约或迁移策略

必须保持的约束

  • 不创建、修改、启用或运行 .github/workflows/ 下任何工作流。
  • 不以 GitHub CI 为发布门槛；格式化、lint、测试、竞态、打包和发布验证在本地运行。
  • 不 force-push、amend 或 squash，除非明确被要求。
  • 提交使用 Conventional Commits，且包含 Assisted-by: AGENT_NAME:MODEL_VERSION trailer；不添加 Co-Authored-By 或 Signed-off-by。
  • 保留仍然相关的注释；新注释简短，只解释原因。

兼容基线

Git 协议、数据库结构与迁移、存储路径、Git LFS、API、Actions 工作流目录、配置键和环境变量别名都是兼容性契约。保持根目录 AGENTS.md 与平台改动面稳定；若确需扩大规则或平台变更，必须先记录范围、迁移/回滚路径和兼容性影响，并保留旧标识直到明确迁移。

文档是交付物

  • 对应的 docs/site/ HTML 页面；

GitHub neko233-com/vbox 验证

本项目的本机 Docker 命令替代使用 C:\tools\vbox 中的 github.com/neko233-com/vbox。验证改动时同步检查 vbox 验证页、Dockerfile/配置不变构建、卷映射和 HTTP 冒烟结果；不要把 Oracle VirtualBox 或 Vagrant 当作本项目的 vbox 提供方。

完成定义

完成不是“代码已改”。完成意味着行为、测试、运维影响和文档相互一致，下一位人类或 Agent 不需要从代码重新推导使用方式。

迁移与 LFS

gitsss import-gitea-http 默认输出 JSON。源和目标可以用站点管理员 Token 文件，或 --source-user 加 --source-password-file（目标同理）。密码放在 0600 文件里，不要放在命令行。不带 --apply 只打印计划。带 --apply 时复制账号、权限、Git、LFS，以及本次新建仓库上的标签、里程碑、Issue、评论、Pull Request、评审线程、Release 说明和附件、Wiki 页面，以及挂在该仓库上的 generic、npm、Maven、PyPI、Helm、Cargo、Debian、Composer、Alpine、NuGet、RubyGems 和容器镜像。Debian 与 Alpine 依赖软件包文件 API 的 composite_key。评审里已解决的行评论会在目标评论创建后标记为已解决。附件和软件包单文件上限 512 MiB，并且下载地址必须和源站同源。Conan 和 Swift 只出现在计划里。

gitsss admin lfs-gc 输出 JSON。不加 --apply 只扫描。默认保留 168 小时，短于 24 小时需要 --force。已登录的站点管理员也可以 POST /api/v1/admin/lfs-gc。

组织内网共享不走 Git。服务器上用 gitsss admin org-share，远程 Agent 用 push/pull 或 /api/v1/orgs/{org}/shares。上传分片可以并发，下载用 HTTP Range。容量和磁盘余量不够时，开始上传前就会返回明确错误。默认每个组织 100 GB、文件 30 天过期，--permanent 或 permanent: true 表示不自动删除。管理员用 gitsss admin org-share usage 或 GET /api/v1/admin/org-share 看磁盘和各组织用量，用 quota --bytes 或 PUT /api/v1/admin/org-share/quota 改上限，0 恢复默认。

纯前端插件放在 custom/public/assets/plugins/manifest.json。后端不执行插件代码。契约见 扩展功能。

版本检查

Agent 用 gitsss update check --json 读取一份 JSON：当前版本、最新版本、need_update、清单是否来自 GitHub，以及每个镜像的可用性与延迟。下载必须带校验和：gitsss update download --output DIR --json。校验失败时进程返回非 0，并且不会留下目标文件。--save 把镜像列表写回 [cron.update_checker]，不改变启动时默认不访问外网的行为，除非同时传入 --enable-schedule。仓库提交日报、周报、月报在已登录且有代码读取权限时提供：GET /{owner}/{repo}/activity/summary。它只统计时间戳，不返回补丁内容。

日常验证优先在本机跑。没有 Docker，或设置了 GITSSS_TASK_NATIVE=1 时，task 直接执行 Make，不启动容器。只编译后端时用 make backend-quick。发布包用 make release-native VERSION=... DIST=dist/...，默认同时编译 2 个目标并用 xz -6 并行压缩。发布脚本拒绝脏工作树，校验前端资产戳，生成源码包、平台 tar.gz、逐文件校验和与 SHA256SUMS 回读；task release:verify 可单独复验。make release 仍是需要 Docker 的 xgo 路径。

企业部署验收

GitSSS 默认 0.0.0.0:5030、关闭注册、组织优先。Gitea 保持 3000，最终切换等待管理员通知。用 tools/agent-ops.py 读取 JSON 状态，用 tools/verify-git.py 做真实客户端验收；Actions 仅在独立实例、独立标签验证。原生兼容用 tools/rehearse-native.py 创建受保护的独立副本并核对全部表，不启动源站任务、不复制大型 Git/LFS 数据。程序内置 /help/ 英文离线说明书。升级 343 数据库后的回退必须恢复备份，不能只换旧二进制。

Cloud Agent 本机工具链

task help 列出目标。没有 Docker 或设置 GITSSS_TASK_NATIVE=1 时直接在宿主机执行 Make；也可运行 TAGS="sqlite sqlite_unlock_notify" make backend、make frontend、make test-backend、make test-frontend。

运行 pnpm 或 Make 前，检查 Node、pnpm 是否符合当前 package.json engines，并从已安装工具链选择兼容版本加入 PATH。

独立开发环境使用 ./gitsss web --port 5030 --pid /tmp/gitsss.pid；健康检查 http://127.0.0.1:5030/api/healthz。首次安装选择 SQLite，设置可用的 SSH 端口或关闭 SSH。Gitea 3000 的切换仍需等待管理员通知。

试运行隔离

测试和副本实例必须隔离 HOME/USERPROFILE、SSH_ROOT_PATH，关闭 SSH_CREATE_AUTHORIZED_KEYS_FILE 和 SSH_CREATE_AUTHORIZED_PRINCIPALS_FILE。禁用或内置 SSH 均不能改写系统授权文件。验收前后核对原 Gitea 授权文件哈希及真实密钥拉取；同机并行服务使用不同 session/remember Cookie 名称。组织 Kanban 与仓库看板分别验证；语言测试覆盖自动识别、手动选择与账户自动偏好，浅色/深色桌面布局均需实屏检查；当前不涉及移动端。发布前将 TypeScript、TSX lint 与 CodeMirror 单实例依赖检查纳入本机门禁。

交接

交接时说明：已改文件和行为、已运行的验证及结果、未运行项目与原因、保留的用户改动，以及需要人工决定的风险。不要把未验证的假设表述为完成。

Git 数据兼容

布局合同 v1 在数据目录的 gitsss/layout.json。升级只能新增 reserved 键和 gitsss/extensions/<id>/ 下的文件，不能移动、重命名、重打包或改写裸仓库、Git 对象、refs 与 LFS 对象。读不懂 layout_version 的程序必须停下来，并且不写这些目录。回滚是换回上一版二进制，Git 与 LFS 不需要数据迁移。

存储稳定性冻结

Git、LFS、本地/S3/MinIO、数据库路径和 Actions 日志/制品存储属于兼容性合同。禁止无报告的大规模重构；新增驱动或观测能力必须保持既有路径、配置键和 API 不变，并同时验证 CGO 与纯 Go SQLite 构建。

组织任务与头像验收

tools/verify-enterprise.py --url http://gitsss.example.internal:5030 --token-file target.token 使用临时私有组织和账号验证全局任务、权限隔离、24 个头像与真实上传裁剪压缩，完成后清理自身数据。仅用于 GitSSS 试运行环境，不对原 Gitea 执行。

首页入口验收

验证公共入口管理员权限、个人入口隔离、HTTP/HTTPS 校验、冲突保护及原页保存；试运行新增 app_state 入口需连同看板导出，接管前核对用户 ID。禁止把企业私有地址作为公开产品默认值。

协作规则与原生上传验收

组织自动团队规则在 /org/{org}/settings/team-rules 管理，只有组织所有者可写；先预览，再对已有仓库显式应用，不批量移除人工授权。规则使用稳定团队 ID，迁移时核对映射。tools/verify-enterprise.py 会创建并清理独立组织、账号与仓库，覆盖规则与越权/CSRF/并发编辑。Express233 内置上传动作使用 Secrets，发布默认关闭；node --test tools/tests/express233-upload.test.cjs 验证流式上传、失败与重试，在独立接收端和独立 Runner 通过后才用于业务。不要为本仓库添加 GitHub workflow。

公开源码信息检查

企业地址、组织标识与凭据保留在内网配置和 Secrets，公开源码只用中性示例。执行 python3 tools/check-public-data.py --deny-file /private/public-deny.json，检查历史增加 --all-history；私有禁止列表必须放在仓库外。报告只输出文件名或对象 ID，不回显命中值。截图和压缩包需另外检查。历史重写须有已验证的私有备份、隔离副本与明确授权；GitHub 只读 PR 引用和缓存不随普通分支替换清除。详见 公开源码与历史清理。

原生接管与生产验证

接管前停止所有写入者并备份原配置、密钥、数据库与二进制；按稳定名称映射试运行数据，不覆盖源 runtime-state。源 Gitea 未填写 DEFAULT_ACTIONS_URL 时显式保留 github；已有值优先。保留原 SSH 命令入口和外部 Runner 凭据。启用原生 Runner 时使用不与旧流程重叠的专用标签，例如 gitsss-native:host，新任务显式选择 gitsss-native。管理员身份不会扩大只读 Token 的 scope；写验收使用临时受控 Token，清理后撤销，不重置源账号密码。

原生二进制安装需在 GitSSS 服务 PATH 提供 Node.js 24。内置 setup-node 在 Linux、macOS 和 Windows 保留真实运行时目录，不自动下载或修改系统运行时。可用独立目录让 GitSSS 与原外部 Runner 使用不同 Node.js 版本。

HTML Docs 与通知管理

Agent 可生成静态 HTML 到 docs/site/ 并通过普通 Git push 更新仓库 Docs。使用相对资源路径、本地 classic/ES module JavaScript 和 JSON 搜索索引；fetch/XHR 限文档目录，不能访问外部 CDN/API 或父页面权限。通知通过现有 REST webhook API 的 config.notification 管理；Webhook URL 与凭据仅放在部署端，投递失败查看平台业务错误码并手工重投。见 完整行为与回滚说明。

测试环境 SSH 隔离

测试初始化把 SSH_ROOT_PATH 固定在独立测试数据目录，并关闭授权文件与 principals 文件生成。运行测试或演练仍需使用独立 HOME/USERPROFILE，不要把生产配置传入测试。仓库 Make 的 test-backend 只运行单元包；integration 需要独立配置与数据库，避免直接无差别运行全仓集成套件。

工作区中心运维

软件中心为组织成员共享空间，默认 100 GiB；只写入布局契约 v1 的独立扩展与现有 app_state，不触碰 Git/LFS。软件目录删除前确认准确 ID 与名称，组织数据目录只支持单写进程。先完成配额、权限、流式传输、Range 与回滚验证。Git HTTP 协议修改必须回归 v0/v1/v2、浅克隆、部分克隆、push/fetch 与 LFS。不得更改已有 sshd 或授权文件。全站 Actions 运维快照仅站点管理员可见；其他成员从有权限的仓库访问工作流。

传输与交互验收

软件中心新增分块上传与虚拟 ZIP64，API、限额、崩溃恢复和回滚规则见 传输兼容性报告。在独立 HOME/SSH_ROOT_PATH 验证错误块校验、偏移冲突、重启恢复、配额、越权、目录循环、批量原子性和 Range 解包。新 Go 依赖为零；浏览器通过 MIT 的 @noble/hashes 在 Worker 中校验，不能假定内网 HTTP 有 Web Crypto 或 File System Access。

桌面界面检查应用开源 ui-skills 的 baseline-ui、fixing-accessibility，以及 Vercel Web Interface Guidelines。复用现有原生 dialog 和 Fomantic，不迁移控件库；删除使用确认框，错误靠近操作位置，图标控件有名称，Tab/方向键/Enter/Escape 可用。自动可访问性扫描配合真实 Edge 交互、明暗配色与 1366/1600 桌面截图；自动扫描通过不代表完整人工无障碍认证。

软件中心传输验收

1.10 的上传源文件、下载分块与偏移保存到浏览器 IndexedDB，按用户与组织隔离。验收须包括普通 HTTP、真实浏览器重开、无需重选文件的恢复、手动暂停保留、取消释放缓存、网络失败重试、Range/ETag 防混版、多标签页租约与缓存不足。下载“待保存”不能描述为本地写盘成功；确认保存后清缓存。保持 Git/SSH/LFS 路径和授权文件不变。

身份与新工作区验收

本地验证 Ctrl+K/⌘K 搜索、日期范围与配置时间戳、HTML 单文件预览及资源隔离、Actions trackId/重跑触发者、注释配色和 shader 降级。三方 OAuth 必须区分本地回调/事务测试与真实供应方授权；没有应用配置时不得伪造登录成功。凭据仅留在私有配置；飞书只读卡片验证不能触发真实 CI 或生产发布。全站界面使用真实桌面浏览器对照设计稿，包含 WebGL 成功、静态回退与动态偏好。

git-next 子仓库与资源验收

git-next 是独立公共子仓库，父仓库 ignore=all，不把实验客户端集成进生产。显式检查子仓库状态和 gitlink。前端生成后执行 node tools/frontend-build.mjs check，校验嵌入资源与实际浏览器布局，不把旧 CSS 配上新模板视为发布通过。

软件中心支持多人和同账号多页签并发上传：每页签独立队列，服务端保留全局八个分块流与既有限额。验收须用至少两个用户、两个同账号页签进行真实并发，并校验摘要；检查刷新恢复、暂停保留、旧缓存兼容和过期所有者不能继续写入。新前端回滚前完成或取消缓存传输。

软件平台整理

Agent 可用软件中心 REST API 列出全量分页数据并按后缀整理，先 POST /api/v1/orgs/{org}/software/organize 获取只读预览，再携带原 revision 和 apply:true 执行。目录结构为平台/原用途；通用压缩格式归全平台，未知后缀保持原处，也可传入显式目的平台。GET 使用 read:organization、POST 使用 write:organization，要求组织成员身份，public-only Token 不可访问。遇到 409 必须重新预览，不重试旧计划；禁止打印令牌。API、兼容性与回滚见 平台分类说明及 请求示例。

客户端子仓库

git-next 与 git-terminal 为同级独立子模块。原生 CLI、内置 LFS、GPUI Fast 桌面和组合 MSI 在子仓库独立构建/验收；不得把历史 Rust 启动器当作桌面终端，不得据此替换生产服务器。范围与恢复边界

日报职能筛选

管理员可在日报 Agent 后台选择全部职能或勾选指定职能。默认包含所有职能及未设置职能的账号；选择指定职能时，账号命中任一所选标签即可，未设置标签的账号会跳过。筛选同时适用于手动和定时运行，仍须将账号分类为个人且有归属的提交。
