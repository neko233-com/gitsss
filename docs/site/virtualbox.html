GitHub neko233-com/vbox 本机验证

用 GitHub neko233-com/vbox 替代 docker 命令，保持 Dockerfile 与配置不变

提供方

vbox 是 C:\Users\14170\Desktop\Code\neko233-Projects\vbox 的本机 checkout，对应 github.com/neko233-com/vbox；它替代的是 docker 命令，不是 Oracle VirtualBox，也不依赖 Docker Desktop/daemon。

安装 vbox

Set-Location 'C:\Users\14170\Desktop\Code\neko233-Projects\vbox'
.\install.ps1

安装并验证 GitSSS

Set-Location 'C:\Users\14170\Desktop\Code\neko233-Projects\gitsss'
.\tools\vbox\gitsss.ps1 -Action check
.\tools\vbox\gitsss.ps1 -Action pull
.\tools\vbox\gitsss.ps1 -Action install
.\tools\vbox\gitsss.ps1 -Action verify

验证使用 vbox run，不调用宿主 Docker。安装器同时提供同目录的 docker.exe 兼容别名，因此现有 Dockerfile、镜像名、卷映射和 Compose 配置无需改写；docker compose 由同一个 vbox 二进制执行。HTTP 地址是 http://127.0.0.1:3000/，Git SSH 地址是 127.0.0.1:2222。持久化目录默认为 %LOCALAPPDATA%\gitsss\vbox-data，映射到容器的 /data。

离线镜像导入

如果 registry 返回 401，但有 GitSSS 发布流程生成的 Docker archive，可直接使用 vbox 导入，不需要 Docker：

.\tools\vbox\gitsss.ps1 -Action load -ImageArchive .\gitsss-image.tar
.\tools\vbox\gitsss.ps1 -Action install -ImageArchive .\gitsss-image.tar
.\tools\vbox\gitsss.ps1 -Action verify -ImageArchive .\gitsss-image.tar

vbox 的 load --input 会读取 Docker save archive，保留 image config、entrypoint、command、环境变量和 layers。

私有镜像

如果 registry 返回 401，先在 vbox 进程环境中设置 VBOX_REGISTRY_USERNAME、VBOX_REGISTRY_PASSWORD，或在 %USERPROFILE%/.docker/config.json 的 auths 中配置凭据；vbox 不调用 Docker credential helper。

卷与兼容性

GitSSS 依赖 vbox 的 --volume HOST:CONTAINER[:ro]。Windows + Linux 镜像会把主机目录映射到 vbox-runtime WSL2，再 bind mount 到 rootfs；停止进程时会 卸载挂载点。Dockerfile 和 Compose 文件本身不变，vbox 负责执行 docker 命令；多机网络和 Swarm 控制面不在本机 vbox 引擎范围内。

.\tools\vbox\gitsss.ps1 -Action verify -KeepRunning
.\tools\vbox\gitsss.ps1 -Action logs
.\tools\vbox\gitsss.ps1 -Action stop
.\tools\vbox\gitsss.ps1 -Action remove
