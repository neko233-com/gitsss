从 Gitea 迁移

两种迁移方式：HTTP 导入（推荐）和 Volume 接管

方式一：HTTP 导入（推荐）

gitsss import-gitea-http 通过 Gitea HTTP API 和 Git HTTP 导入账号、仓库和权限。不需要 SSH、源服务器文件系统或 Docker Volume 访问权限。

安全性

源 Gitea 保持运行且不被修改。导入使用只读 GET 操作，Dry-run 为默认行为。

导入范围

导入不导入
  • 所有账号及账号状态
  • 组织、团队、RBAC 权限
  • 仓库元数据、分支、标签
  • 完整 Git 对象和 LFS 对象
  • 公共组织成员关系
  • 直接协作者权限
  • 标签、里程碑、Issue、评论、Pull Request、评审、Release 说明和附件、Wiki、generic 软件包
  • npm、Maven、容器等非 generic 软件包字节
  • Webhooks、Secrets
  • SSH 密钥、TOTP
  • 密码哈希、OAuth
  • Access Tokens
注意

HTTP 无法导出密码哈希、TOTP 密钥、API Token 或 SSH 私钥。导入的本地用户会收到随机临时密码，首次登录强制修改。

Step 1: 准备凭据

源站和目标站都要使用站点管理员。可以是 API Token，也可以是用户名加密码文件。密码不要写在命令行上。

# 密码或 token 都放进 0600 文件。下面是用户名密码方式。
printf '%s\n' 'source-admin-password' > source.password
printf '%s\n' 'target-admin-password' > target.password
chmod 600 source.password target.password

Step 2: 演练（Dry-run）

先在临时端口启动 gitsss，执行 dry-run 验证导入计划：

gitsss import-gitea-http \
  --source-url http://git.example.internal:3000 \
  --source-user root \
  --source-password-file source.password \
  --target-url http://127.0.0.1:5300 \
  --target-user root \
  --target-password-file target.password \
  --all-repos

审查 JSON 计划。它包含账号、组织、仓库，以及标签、里程碑、Issue 和 Pull Request。Dry-run 不写目标站。

Step 3: 执行导入

确认无误后，使用 --apply 执行实际导入：

gitsss import-gitea-http \
  --source-url http://git.example.internal:3000 \
  --source-user root \
  --source-password-file source.password \
  --target-url http://127.0.0.1:5300 \
  --target-user root \
  --target-password-file target.password \
  --all-repos \
  --timeout 30m \
  --apply \
  --credentials-file imported-users.jsonl

Step 4: 切换到生产端口

  1. 保留源 Gitea 回滚数据
  2. 在审批窗口期内停止源 Gitea
  3. 将 gitsss 端口从临时 3001 改为 3000
  4. 启动 gitsss 并验证 /api/healthz、登录、克隆、推送、LFS、RBAC
  5. 删除源 Token，安全归档或销毁临时凭据

方式二：Volume 接管

当需要完整保留密码哈希、TOTP、SSH 密钥、Wiki、Release 等数据库状态时，使用 Volume 接管。Issue 和 Pull Request 已可以由 HTTP 导入复制到新建仓库。

警告

不要复制正在运行的数据库。必须先停止 Gitea，保留不可变快照和回滚副本。

准备候选 Volume

sh contrib/prepare-gitea-takeover.sh \
  --source-volume gitea-data \
  --target-volume gitsss-takeover-candidate \
  --image gitsss/gitsss:VERSION

该工具会：

  • 拒绝任何正在运行容器挂载的源 Volume
  • 仅使用本地 gitsss 镜像，禁用网络
  • 以只读方式挂载源 Volume
  • 保留数字所有权
  • 比较内容和文件系统元数据的 SHA-256

启动 gitsss

export GITSSS_DATA_VOLUME=gitsss-takeover-candidate
export GITSSS_IMAGE=gitsss/gitsss:VERSION
docker compose up -d
重要

首次启动 gitsss 时不要指向源 Volume。如果验收失败，停止 gitsss，仅删除候选 Volume，然后重启未修改的 Gitea 源 Volume。
