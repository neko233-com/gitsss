运维指南

离线部署、Mac mini M4、存储管理

离线生产策略

gitsss 启动和运行完全不需要外部网络。更新检查器默认关闭，Actions Runner 不会下载未知远程 Action。

更新检查

如需启用公司内部更新检查，配置 app.ini：

[cron.update_checker]
ENABLED = true
HTTP_ENDPOINT = http://updates.intranet.example/gitsss/version.json

构建镜像时使用公司镜像

Docker 构建支持以下 Build Args 指向公司内部镜像：

docker buildx build \
  --build-arg NPM_REGISTRY=https://npm.intranet.example/ \
  --build-arg GOPROXY=https://goproxy.intranet.example/ \
  --build-arg UBUNTU_MIRROR=https://mirrors.intranet.example/ubuntu \
  --build-arg UBUNTU_PORTS_MIRROR=https://mirrors.intranet.example/ubuntu-ports \
  --platform linux/amd64,linux/arm64 \
  --load -t gitsss/gitsss:latest .

这些参数仅影响构建时依赖获取，运行时不配置。

Mac mini M4 部署

Mac mini M4 运行 linux/arm64 镜像，通过 Docker Desktop 的虚拟化层运行。

离线镜像传输

# 在构建机器上导出
docker buildx build --platform linux/arm64 --load -t gitsss/gitsss:VERSION .
docker save gitsss/gitsss:VERSION -o gitsss-VERSION-linux-arm64.oci.tar
shasum -a 256 gitsss-VERSION-linux-arm64.oci.tar > gitsss-VERSION-linux-arm64.oci.tar.sha256

# 在 Mac mini 上验证并加载
shasum -a 256 -c gitsss-VERSION-linux-arm64.oci.tar.sha256
docker load -i gitsss-VERSION-linux-arm64.oci.tar

启动服务

export GITSSS_IMAGE=gitsss/gitsss:VERSION
export GITSSS_ROOT_URL=http://192.168.110.42:3000/
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:3000/api/healthz
SSH 端口

SSH 默认发布为 2222，避免与 macOS Remote Login 冲突。如需其他端口，在首次启动前设置 GITSSS_SSH_PORT。

存储管理

存储感知面板位于 /-/admin/storage，提供以下信息：

  • Volume 健康状态
  • 分类存储统计
  • 每个仓库的 Git/LFS 字节数

手动清理

使用短期扫描 Token 和显式确认进行清理。仅删除过期条目，以下内容受保护：

  • 仓库数据
  • LFS 对象
  • 数据库
  • 未知路径

清理范围仅限于临时目录、Actions 工作目录和 Actions 缓存根目录下的过期内容。

备份与恢复

备份

# 停止服务
docker compose stop

# 备份数据卷
docker run --rm -v gitsss-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/gitsss-backup-$(date +%Y%m%d).tar.gz /data

# 重启服务
docker compose start

恢复

# 停止服务
docker compose stop

# 恢复数据卷
docker run --rm -v gitsss-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/gitsss-backup-YYYYMMDD.tar.gz -C /"

# 重启服务
docker compose start

日志

日志位于安装目录的 logs/ 子目录：

平台路径
WindowsC:\gitsss\logs\
Linux/opt/gitsss/logs/
macOS/opt/gitsss/logs/

也可使用 docker compose logs -f 实时查看容器日志。

健康检查

# API 健康检查
curl --fail http://localhost:3000/api/healthz

# 容器状态
docker ps --filter name=gitsss

# 详细容器信息
docker inspect gitsss --format '{{.State.Health.Status}}'
