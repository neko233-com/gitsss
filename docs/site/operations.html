运维指南

离线部署、Mac mini M4、存储管理

本机验证

本机 Docker 命令替代使用 C:\tools\vbox 中的 github.com/neko233-com/vbox。它提供 docker.exe 兼容别名，Dockerfile 和常用 Compose 配置无需改写；完整命令见 vbox 验证。

离线生产策略

gitsss 启动和运行完全不需要外部网络。更新检查器默认关闭，Actions Runner 不会下载未知远程 Action。

公网入口与登录防护

[security] LOGIN_PROTECTION_ENABLED = true 默认开启。网页账号或账号与来源组合连续失败 5 次后要求本地一次性验证码；一分钟内账号 10 次、组合 5 次、来源 60 次尝试，或来源 15 分钟内失败 30 次，也会要求验证。正常登录不永久锁账号，也不整段封禁共用出口 IP。

HTTP Basic 新密码尝试每分钟限制：账号与来源组合 10 次、账号 30 次、来源 120 次；超出返回 429 和 Retry-After。近期验证成功的凭据可绕过异常尝试预算，但每次仍重新校验密码、账号状态及二次验证。访问令牌优先验证，SSH 不变。正常网页验证也是新客户端恢复 Git HTTP 访问的入口。同一出口受到攻击时，首次网页登录可能需要验证码，首次 Basic 密码请求可能需要短暂重试。

TOTP 与恢复码在密码已正确后共用每账号每分钟 10 次预算。最多并发验证 16 个密码，记录 32,768 个限速项和 4,096 个凭据 HMAC；不保存明文密码。计数在进程内保存并过期，重启清空，多进程之间不共享。验证码和限速不能替代强密码、TOTP 或网络层抗 DDoS。

可信代理仅填写精确地址或网段，公网部署不要设为 *。从右向左检查 X-Forwarded-For，遇到首个非可信节点停止，最多检查 REVERSE_PROXY_LIMIT 跳；优先使用此链而非 X-Real-IP。直接客户端伪造的来源与协议头会被忽略。

TLS 入口应覆盖客户端传入的转发头。若 frp 把 X-Forwarded-Proto 改成内部 HTTP，可在 TLS 入口覆盖 X-Original-Proto，并配置 REVERSE_PROXY_PROTO_HEADER = X-Original-Proto。默认仍使用 X-Forwarded-Proto。frps 的 HTTP 后端端口必须仅对代理开放，IPv4、IPv6 都要检查，避免绕过 HTTPS。公网虚拟主机为 Cookie 设置 Secure，原有内网 HTTP 可独立保留。

升级不修改数据库、Git/LFS 路径、SSH 密钥或对象。回滚使用旧二进制和配置；独立恢复代理配置与后端端口规则。升级前后用隔离账号验证验证码、同出口登录、Token 与 MFA，并验证实际公网来源和原有 Git/SSH/LFS。完整阈值、代理配置示例、验收与回滚见仓库 docs/operations/public-access.md。

更新

更新时必须保留原安装目录与 Docker 数据卷。获取新的离线镜像包后，用原来的端口、根 URL、安装目录和数据卷重跑安装器；安装器加载镜像、更新安装目录文件并重建容器，不会删除现有数据。

# PowerShell
.\install\install.ps1 -ImageArchive .\gitsss-image-new.tar -InstallDir C:\gitsss -DataVolume gitsss-data -Port 3000 -RootUrl http://gitsss.intranet:3000/

# Linux / macOS
./install/install.sh --image-archive ./gitsss-image-new.tar --install-dir /opt/gitsss --data-volume gitsss-data --port 3000 --root-url http://gitsss.intranet:3000/
凭据

已有数据卷更新时不要重新传入初始管理员凭据；已有账户和密码不会被重置。

卸载

先停止并移除容器。以下命令保留数据卷，可用于重新安装或恢复；删除数据卷会永久删除仓库、用户、Issue 和 Actions 数据。

# 所有平台：停止服务，保留数据
docker compose --project-directory INSTALL_DIR down

# Windows：移除自动启动项
Unregister-ScheduledTask -TaskName 'GitSSS Background' -Confirm:$false -ErrorAction SilentlyContinue
Remove-Item "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\GitSSS Background.vbs" -Force -ErrorAction SilentlyContinue

# Linux：禁用自动启动
sudo systemctl disable --now gitsss.service
sudo rm /etc/systemd/system/gitsss.service
sudo systemctl daemon-reload

# macOS：移除用户级自动启动
launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.gitsss.autostart.plist"
rm -f "$HOME/Library/LaunchAgents/com.gitsss.autostart.plist"
不可恢复

确认备份可用后，才可执行 docker volume rm gitsss-data。非默认数据卷请替换为实际名称。

更新检查

启动和日常访问不会自动连接 GitHub。需要检查版本时，管理员打开 /-/admin/updates，或执行 gitsss update check --json。镜像按可用性和延迟排序，下载失败时按该顺序回退；sha256 不匹配的包会被丢弃。默认镜像是 https://ghfast.top，可在配置或命令行替换为多个内网地址。

[cron.update_checker]
ENABLED = true
CHECK_GITHUB = true
MIRRORS = https://ghfast.top
HTTP_ENDPOINT = http://updates.intranet.example/gitsss/version.json

gitsss update check --json
gitsss update download --output /tmp

远程仓库交接验证

仓库内置只读验证脚本，检查健康接口、Swagger、仓库页面、Smart HTTP 引用、Git LFS 与工作流文件，不会推送、建 tag 或修改远程数据。

最近一次 Windows 生产门禁记录于 docs/verification/production-readiness-2026-08-10.md：包含本机视觉、管理员、Actions Worker、Git/LFS 操作、缓存清理与发布前检查结果。

# PowerShell（密码只从隐藏输入读取，不写入 URL）
$env:GITSSS_REMOTE_PASSWORD = Read-Host "Remote password" -AsPlainText
.\scripts\verify-remote.ps1 -BaseUrl http://git.example.internal:3000

# Linux / macOS
GITSSS_REMOTE_PASSWORD='...' ./scripts/verify-remote.sh

构建镜像时使用公司镜像

Docker 构建支持以下 Build Args 指向公司内部镜像：

docker buildx build \
  --build-arg NPM_REGISTRY=https://npm.intranet.example/ \
  --build-arg GOPROXY=https://goproxy.intranet.example/ \
  --build-arg UBUNTU_MIRROR=https://mirrors.intranet.example/ubuntu \
  --build-arg UBUNTU_PORTS_MIRROR=https://mirrors.intranet.example/ubuntu-ports \
  --platform linux/amd64,linux/arm64 \
  --load -t gitsss/gitsss:latest .

这些参数仅影响构建时依赖获取，运行时不配置。

Mac mini M4 部署

Mac mini M4 运行 linux/arm64 镜像，通过 Docker Desktop 的虚拟化层运行。

离线镜像传输

# 在构建机器上导出
docker buildx build --platform linux/arm64 --load -t gitsss/gitsss:VERSION .
docker save gitsss/gitsss:VERSION -o gitsss-VERSION-linux-arm64.oci.tar
shasum -a 256 gitsss-VERSION-linux-arm64.oci.tar > gitsss-VERSION-linux-arm64.oci.tar.sha256

# 在 Mac mini 上验证并加载
shasum -a 256 -c gitsss-VERSION-linux-arm64.oci.tar.sha256
docker load -i gitsss-VERSION-linux-arm64.oci.tar

启动服务

export GITSSS_IMAGE=gitsss/gitsss:VERSION
export GITSSS_ROOT_URL=http://git.example.internal:3000/
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:3000/api/healthz
SSH 端口

SSH 默认发布为 2222，避免与 macOS Remote Login 冲突。如需其他端口，在首次启动前设置 GITSSS_SSH_PORT。

存储管理

存储感知面板位于 /-/admin/storage，提供以下信息：

  • Volume 健康状态
  • 分类存储统计
  • 每个仓库的 Git/LFS 字节数

手动清理

使用短期扫描 Token 和显式确认进行清理。仅删除过期条目，以下内容受保护：

  • 仓库数据
  • LFS 对象
  • 数据库
  • 未知路径

清理范围仅限于临时目录、Actions 工作目录和 Actions 缓存根目录下的过期内容。

备份与恢复

备份

# 停止服务
docker compose stop

# 备份数据卷
docker run --rm -v gitsss-data:/data -v $(pwd):/backup \
  alpine tar czf /backup/gitsss-backup-$(date +%Y%m%d).tar.gz /data

# 重启服务
docker compose start

恢复

# 停止服务
docker compose stop

# 恢复数据卷
docker run --rm -v gitsss-data:/data -v $(pwd):/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/gitsss-backup-YYYYMMDD.tar.gz -C /"

# 重启服务
docker compose start

日志

日志位于安装目录的 logs/ 子目录：

平台路径
WindowsC:\gitsss\logs\
Linux/opt/gitsss/logs/
macOS/opt/gitsss/logs/

也可使用 docker compose logs -f 实时查看容器日志。

健康检查

# API 健康检查
curl --fail http://localhost:3000/api/healthz

# 容器状态
docker ps --filter name=gitsss

# 详细容器信息
docker inspect gitsss --format '{{.State.Health.Status}}'
