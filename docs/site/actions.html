离线 Actions

内置 CI/CD，无需公网访问

概述

gitsss 将服务端、内置 Runner、Node.js、Go、Git LFS、Docker 和常用 Action 打包在一个 Ubuntu 24.04 镜像中。启动后无需任何外部依赖即可运行 CI/CD 工作流。

安全策略

未知远程 Action 在离线模式下会明确失败，不会尝试访问公网。仓库任务运行在独立容器内，每个任务使用私有 Docker daemon，不能访问宿主 Docker socket。

内置 Action

Action用途
actions/checkout检出仓库代码
actions/cache缓存依赖（pnpm、npm、Go modules 等）
actions/upload-artifact上传构建产物
actions/download-artifact下载构建产物
actions/setup-node配置 Node.js 环境
actions/setup-go配置 Go 环境

编写工作流

系统同时识别仓库根目录的 .github/workflows/ 与兼容目录 .gitea/workflows/。新项目建议使用前者；现有内网仓库无需迁移目录即可继续运行。

Node.js 项目示例

# .github/workflows/ci.yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: pnpm install --frozen-lockfile
      - run: pnpm test

Go 项目示例

# .github/workflows/ci.yaml
name: CI
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.26'
      - run: go build ./...
      - run: go test -race ./...

多阶段构建示例

# .github/workflows/release.yaml
name: Release
on:
  push:
    tags: ['v*']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.26'
      - run: go build -o dist/app ./cmd/app

  test:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - uses: actions/checkout@v4
      - run: go test ./...

容器隔离

每个 Actions Job 运行在独立容器中，具有以下安全特性：

  • 独立的 Docker daemon — 不共享镜像、容器、网络或卷
  • 不能访问宿主 Docker socket
  • 资源限制：默认 4 CPU、8GB 内存、2048 PID
  • 中断的任务资源在 Runner 启动时自动清理

可通过环境变量调整资源限制：

GITSSS_ACTIONS_CONTAINER_OPTIONS=--cpus=8 --memory=16g --pids-limit=4096

缓存与产物

Actions 缓存和产物存储在 gitsss 数据卷中，重启后保留。可通过 Web 管理界面或 API 管理。

故障排查

问题原因解决
Action 下载失败 未知远程 Action 使用内置 Action 或自行构建离线 Action
Job 容器启动失败 Docker 资源不足 检查磁盘空间和 Docker daemon 状态
Runner 无法连接 端口 8088 不通 确认 127.0.0.1:8088 可访问
