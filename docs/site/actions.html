离线 Actions

内置 CI/CD，无需公网访问

提交与触发追踪

运行列表显示触发事件、账号与备注，以及链接到完整提交的 trackId。运行摘要单独展示 trackId；重新运行时以当前 attempt 的操作人为准，原始提交与发起账号继续保留在运行数据中。push、定时、手动和重跑保留各自原因，不因查看页面而执行任何工作流。

概述

gitsss 将服务端、内置 Runner、Node.js、Go、Git LFS、Docker 和常用 Action 打包在一个 Ubuntu 24.04 镜像中。默认使用服务进程内置 Runner，启动后无需外部 Docker 服务、Runner 注册进程或公网依赖即可运行 CI/CD 工作流。

Linux 和 macOS 都不需要像 Gitea 那样另外下载 act_runner。服务进程直接领取 self-hosted:host、ubuntu-latest:host、ubuntu-24.04:host。这些标签沿用 GitHub 习惯，任务在 gitsss 所在主机上执行。macOS 上的 ubuntu-latest:host 也是在这台 Mac 上跑，不会另起一台 Ubuntu 虚拟机。

管理员 Runner 管理

管理员打开 管理后台 → Actions → Runners 即可看到内置 Runner 的状态、容量和标签，并可直接启动、停止或重启内置 Runner。内置 Runner 默认名为 gitsss-builtin，与服务进程同生命周期；现有列表仍支持禁用、编辑和管理外部 Runner。

Docker 兼容模式

默认的内置 Runner 不读取 /var/run/docker.sock，因此可直接运行在 vbox 等 Docker 命令兼容运行时中。只有将 BUILTIN_RUNNER_ENABLED 设为 false、改用外部 Docker Runner 时，才需要提供可用的 Docker socket。

首页 Worker 运营面板

首页 Actions Worker 面板显示当前运行中与排队中的 Job，运行中任务始终置顶；已完成任务不进入列表，只保留最近一次完成结果。可按仓库、任务名、Runner、提交 SHA 或工作流搜索，面板同时给出 Runner 总量、在线状态、24 小时成功数与失败数，便于快速判断内网 CI 是否已触发、正在执行或已经失败。

安全策略

未知远程 Action 在离线模式下会明确失败，不会尝试访问公网。仓库任务运行在独立容器内，每个任务使用私有 Docker daemon，不能访问宿主 Docker socket。

编写工作流

系统同时识别仓库根目录的 .github/workflows/ 与兼容目录 .gitea/workflows/。新项目建议使用前者；现有内网仓库无需迁移目录即可继续运行。

Node.js 项目示例

# .github/workflows/ci.yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: pnpm install --frozen-lockfile
      - run: pnpm test

Go 项目示例

# .github/workflows/ci.yaml
name: CI
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.26'
      - run: go build ./...
      - run: go test -race ./...

多阶段构建示例

# .github/workflows/release.yaml
name: Release
on:
  push:
    tags: ['v*']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.26'
      - run: go build -o dist/app ./cmd/app

  test:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - uses: actions/checkout@v4
      - run: go test ./...

容器隔离

每个 Actions Job 运行在独立容器中，具有以下安全特性：

  • 独立的 Docker daemon — 不共享镜像、容器、网络或卷
  • 不能访问宿主 Docker socket
  • 资源限制：默认 4 CPU、8GB 内存、2048 PID
  • 中断的任务资源在 Runner 启动时自动清理

可通过环境变量调整资源限制：

GITSSS_ACTIONS_CONTAINER_OPTIONS=--cpus=8 --memory=16g --pids-limit=4096

缓存与产物

Actions 缓存和产物存储在 gitsss 数据卷中，重启后保留。可通过 Web 管理界面或 API 管理。

问题原因解决

原生 Express233 上传

程序内置 gitsss/express233-upload@v1，Runner 需要 Node.js 24，无需 npm 依赖或外网下载 Action。使用 Actions 变量保存 server、project-id，Secret 保存 token（也可 username + password），不把企业地址与凭据写入仓库。

- uses: gitsss/express233-upload@v1
  with:
    server: ${{ vars.EXPRESS233_SERVER }}
    project-id: ${{ vars.EXPRESS233_PROJECT_ID }}
    token: ${{ secrets.EXPRESS233_TOKEN }}
    version: 1.0.${{ github.run_number }}
    path: build/output
    publish: 'false'

path 为工作区内文件或目录，每行一个；不展开 glob，拒绝越界、符号链接和 .git。先建立新草稿，已存在版本直接失败。逐文件流式上传并保留相对路径，不另复制整个压缩包。Express233 按原 API 自动解压 ZIP/TAR/TGZ。默认只上传草稿；publish=true 会发布并可能触发现有部署钩子与 Pull Agent 跟随，必须按业务显式启用。

上传失败保留草稿供检查；网络、429、5xx 默认最多重试两次，仅重试文件上传。创建、发布请求不自动重试；连接结果不明时先检查接收端。timeout-seconds 默认为 300（10–3600），retries 为 0–5，tags 为每行一个标签。拒绝重定向和 URL 账号密码，保留 TLS 校验，日志屏蔽凭据且不回显接收端错误正文。HTTP 内网可用，支持 HTTPS 时优先使用 HTTPS。

输出 version、file-count、manifest-path。清单在 RUNNER_TEMP 记录输入文件路径、大小、SHA256 和真实仓库/ref/commit，上传途中输入改变会失败，任务摘要标明草稿或已发布。清单不修改 Express233 VCS 契约。详见 参数、测试与恢复说明。

已有 Runner 与原生任务

原生接管保留原外部 Runner 的身份与凭据。源站未填写 DEFAULT_ACTIONS_URL 时显式保留上游 github，不能沿用新安装的 self 默认值。原生 Runner 可用独立标签 gitsss-native:host 并存，工作流通过 runs-on: gitsss-native 选择内置 checkout、setup-node、cache 与 artifact v4+。外部 Runner 上的 GitHub artifact v4+ SDK 可能拒绝非 GitHub 服务，使用适配的 Gitea Action 或选择原生 Runner。所有任务均在自托管机器执行，不使用 GitHub 托管工作流。

原生二进制安装需在 GitSSS 服务 PATH 提供 Node.js 24。内置 setup-node 在 Linux、macOS 和 Windows 保留真实运行时目录，不自动下载或修改系统运行时。可用独立目录让 GitSSS 与原外部 Runner 使用不同 Node.js 版本。
