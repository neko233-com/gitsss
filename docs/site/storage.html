存储与 Git LFS

面向游戏仓库的大文件、并发访问与可扩展存储基线

生产原则

Gitsss 不改变 Git 对象模型。高频源码走 Git，二进制资产走 Git LFS；不要把游戏构建包、贴图缓存或中间产物直接提交到普通 Git blob。

升级时保持不动的数据

裸仓库路径、仓库里的 objects/refs，以及 LFS 对象 oid 是冻结数据。程序升级只允许在数据目录新增 gitsss/layout.json 和 gitsss/extensions/。这个旁路文件不在任何 Git 仓库内部。启动时如果发现更新的布局版本，进程会退出，避免旧程序改写仓库。

推荐拓扑

Git 客户端
  ├─ Git smart HTTP / SSH → Git 对象存储
  └─ Git LFS batch API     → LFS 对象存储（对象存储优先）

元数据与权限 → PostgreSQL（生产）
单机试用     → SQLite + 本地卷（不建议多节点）

Git 仓库、附件、LFS、包和 Actions 日志使用独立存储配置，可分别迁移到 MinIO/S3 兼容服务或 Azure Blob。多节点部署必须使用共享对象存储，并让所有节点使用同一数据库和密钥。

SQLite 单机模式仍兼容既有 sqlite3 配置；无 C 工具链的平台可使用 CGO_ENABLED=0 go build -tags sqlite，内置纯 Go 驱动，不改变 XORM、数据库路径或迁移合同。

游戏资产策略

  • Unity/Unreal 文本资产、脚本和配置：普通 Git，便于差异审查。
  • FBX、GLB/GLTF、OBJ、贴图、音频、视频和构建包：Git LFS；提交前配置 .gitattributes。
  • 持续集成缓存与临时构建产物：使用 Actions/外部制品存储，不进入长期 Git 历史。
  • 大规模迁移前先做裸仓库备份、LFS 校验和恢复演练；删除历史对象前保留不可变快照。

仓库内的常见可预览格式包括图片、SVG、PDF、音频、视频，以及 3D Viewer 支持的 3DM、3DS、3MF、AMF、BIM、BREP、DAE、FBX、FCSTD、GLB、GLTF、IFC、IGES、STEP、STL、OBJ、OFF、PLY、WRL。TGA 与 DDS（DXT1/3/5）可直接画布预览，KTX/KTX2、Basis、HDR、EXR 等无法安全或离线解码的格式仍提供原始下载和源码查看；Unity Prefab/Scene/Asset、Godot TSCN/TRES、Shader 等文本资产使用代码查看，不伪造专有格式预览结果。

# .gitattributes
*.fbx filter=lfs diff=lfs merge=lfs -text
*.glb filter=lfs diff=lfs merge=lfs -text
*.gltf filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text

关键配置

[database]
DB_TYPE = postgres
HOST = postgres:5432
NAME = gitsss
USER = gitsss

[storage]
STORAGE_TYPE = minio
MINIO_ENDPOINT = minio:9000
MINIO_BUCKET = gitsss
MINIO_USE_SSL = false

[lfs]
STORAGE_TYPE = minio
MINIO_BUCKET = gitsss-lfs
LFS_MAX_FILE_SIZE = 10737418240

实际密钥使用环境变量或密钥文件注入，不要把访问密钥提交到仓库。对象存储启用版本保护/生命周期策略前，先确认不会删除仍在 Git LFS 引用中的对象。

性能与稳定性门禁

  • 数据库使用 PostgreSQL，并配置连接池、慢查询日志和定期备份。
  • 对象存储使用内网低延迟链路，校验上传/下载、断点续传、并发 LFS batch 与失败重试。
  • Git 仓库定期执行维护任务；大规模 GC 前确认没有并发推送，并保留备份。
  • 上线前做 clone、fetch、push、LFS checkout、权限拒绝和故障恢复演练。

存储可观测性

管理员可在 /-/admin/storage 查看卷可用空间、仓库 Git/LFS 字节数和待清理对象。任何写保护状态都应先处理底层磁盘或对象存储告警，再恢复写入。

LFS 清理

游戏仓库会留下指针已经删除的 LFS 对象。gitsss admin lfs-gc 默认只扫描并输出 JSON。--apply 才删除，而且只删除早于 --older-than（默认 168 小时）的元数据。短于 24 小时会被拒绝，除非加上 --force。管理页是 /-/admin/lfs-gc，API 是 POST /api/v1/admin/lfs-gc。对象路径和 oid 布局不变。说明见 docs/operations/lfs-gc.md。

服务端 Git 配置会把 lfs.concurrenttransfers 设成 CPU 数，最多 8。这只影响传输并发，不改变对象存放位置。
