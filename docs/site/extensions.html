扩展功能

选择正确扩展点，保持 Gitea 兼容、离线运行与可维护文档

扩展模型

gitsss 没有运行时插件市场。产品能力以受版本控制的源代码、配置和内置 Actions 扩展；这使离线交付、审计与升级边界保持确定。

先选扩展边界

目标首选位置同时更新
新的业务领域或可复用能力models/、services/、modules/测试、架构与功能文档
HTTP 页面、表单或 APIrouters/、templates/、web_src/用户指南、权限与 API 说明
默认值或部署行为options/、compose.yaml、install/配置、快速开始、运维文档
离线 CI 能力actions/、runner/Actions 支持矩阵、示例工作流
主题或界面样式web_src/、templates/用户可见行为与截图/视觉验证

实现路径

  1. 在 架构设计中确认产品边界和兼容性约束。
  2. 搜索相邻领域已有的 model、service、router、template 和前端实现；复用现有权限、审计、错误处理与配置模式。
  3. 将领域逻辑放在 service/module 层；router 仅负责 HTTP 编排，template 与前端仅负责展示和交互。
  4. 为新配置提供安全默认值、安装器参数或明确的 app.ini 说明；不得让运行时隐式访问公网。
  5. 增加可隔离的单元测试；再按变更范围运行格式化、静态检查与必要集成/E2E 验证。

数据与兼容性

数据模型变更必须增量、可迁移，并保护既有 Gitea 数据语义。不得破坏数据库 ID、密码哈希、仓库路径、LFS 对象、SSH 密钥、Token、Actions 数据或 app.ini 行为。

升级边界

涉及 schema、存储、认证、权限、Git 协议或 Actions 的变更，先写迁移/回滚方案，再开始实现。验证必须覆盖已有数据与新数据。

离线 Actions 扩展

仅将经过审查的 Action 与所需运行时随产品镜像交付。未知远程 Action 必须显式失败，不能在工作流运行时下载代码或镜像。

  • 把内置 Action、入口脚本和依赖纳入 actions/ 与镜像构建输入。
  • 在 离线 Actions页面新增支持范围、输入/输出、示例和限制。
  • 验证 Job 容器隔离、缓存、产物和失败提示；不要扩大 Docker socket 暴露范围。

扩展验收清单

  • 产品边界、权限、数据兼容和离线行为已评审。
  • 默认配置安全，安装、更新、卸载路径已考虑。
  • 对应的单元/集成/E2E 测试与本地验证已执行。
  • 相关 Markdown、HTML 用户文档、导航与 AGENTS.md 已同步更新。

执行命令与提交规则见 开发指南；人类与自动化协作者的交接规则见 Agent 协作。
