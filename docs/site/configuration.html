管理员与内网账户邀请

管理员可在 /-/admin/users/invites 生成一次性账户邀请链接，有效期可选 1 小时至 7 天。链接只保存哈希、过期后自动失效，使用时在数据库事务内消费；账户创建失败会回滚消费。

邀请开户采用内网友好的最低 6 位密码，不强制复杂度和泄漏库检查。普通登录对账号与来源 IP 记录短期失败退避，只延迟错误响应，不设置账号永久锁定；正确密码不会因为他人猜测而被阻断。

API 文档

内置 Actions Runner

Actions 默认启动一个由服务端管理的 Runner，直接使用现有 Actions API，不需要单独注册 Runner 进程。默认标签为 self-hosted:host、ubuntu-latest:host、ubuntu-24.04:host，并发数为 2；工作区和缓存位于数据目录下的 actions/builtin-runner。

[actions]
BUILTIN_RUNNER_ENABLED = true
BUILTIN_RUNNER_CAPACITY = 2
BUILTIN_RUNNER_LABELS = self-hosted:host,ubuntu-latest:host,ubuntu-24.04:host

如果使用外部 Runner 集群，可将 BUILTIN_RUNNER_ENABLED 设为 false。默认值为 true 时不依赖 /var/run/docker.sock，可在 vbox 这类 Docker 命令兼容运行时中直接启动；切换到外部 Docker Runner 后，才需要提供可用的 Docker socket。数据库、Git、LFS、Actions 日志与制品存储合同不变。

接管原来的 Gitea

默认 HTTP 端口是 5300。用 gitsss import-gitea-http --all-repos 导入源站管理员可见的全部仓库，同时导入用户、组织、团队和仓库权限。导入完成后，在 /-/admin/takeover 把端口改成 3000。HTTP 会先绑定新端口，成功后才关闭旧端口，并改写 ROOT_URL。Git 仓库路径和 LFS 对象不动。对公网开放时，这个接口只接受已登录的站点管理员；API 为 POST /api/v1/admin/listen-port，需要管理员令牌，不要把令牌放进 URL。

版本更新检查

服务启动时不会访问 GitHub。管理员可在 /-/admin/updates 立即检查，或显式打开定时任务。检查对象是 neko233-com/gitsss 的 GitHub Releases。直连 api.github.com 与配置的 HTTP 镜像会并行探测；能连上 GitHub 时以官方清单和 sha256 为准，下载时优先用延迟最低的可用地址，失败再按延迟顺序回退。

镜像列表留空时使用内置前缀代理 https://ghfast.top，适合中国大陆等无法直接访问 GitHub 的网络。可以改成任意多个 http/https 前缀，或使用 {url} 模板。建议在内网提供自己的镜像，替换公共代理。

[cron.update_checker]
ENABLED = true
CHECK_GITHUB = true
GITHUB_REPO = neko233-com/gitsss
MIRRORS = https://ghfast.top,https://updates.intranet.example/github/{url}
PROBE_TIMEOUT = 4s
HTTP_ENDPOINT = http://updates.intranet.example/gitsss/version.json

HTTP_ENDPOINT 仍是可选的内网清单，响应上限 1 MiB，可以是 GitHub Release JSON，或包含 latest.version 的旧格式。CHECK_GITHUB 缺省为 false；它和 HTTP_ENDPOINT 都为空时，即使定时任务已启用也不会发起网络请求。

命令行可以检查并下载经过校验的包，不会替换正在运行的进程：

gitsss update check --json
gitsss update check --mirror https://mirror.example --mirror https://backup.example/{url} --save
gitsss update download --asset gitsss-linux-amd64.tar.gz --output /tmp
