开发指南

本地开发、代码规范、测试与发布

前置条件

  • Task — 任务运行器
  • Docker — 构建容器镜像；日常编译和测试可以不启动它
  • Go 1.27.2 — 后端开发与发布工具链
  • Node.js LTS + pnpm — 前端开发

前端依赖使用 pnpm-workspace.yaml 管理 overrides 与构建脚本许可，默认使用冻结锁文件安装；Scarf 安装分析已关闭，适合内网和离线构建。

Docker 可用时，task fmt、task test:go 仍走容器，保证环境一致。没有 Docker，或设置 GITSSS_TASK_NATIVE=1 时，这些命令直接在本机执行。只要后端二进制时用 make backend-quick，它不会再全仓库跑 go generate。

快速开始

# 查看所有可用命令
task help

# 本地构建并运行
task build
task start

常用命令

命令用途
task help查看所有可用 Task 目标
task fmt格式化 Go 和前端代码
task lint:goGo 静态检查（golangci-lint）
task lint:jsJS/TS 静状检查（eslint）
task test运行全部测试
task vbox:verify使用 github.com/neko233-com/vbox 替代 Docker 做本机 GitSSS HTTP 验证
task build构建前后端。Docker 可用时在容器里执行
make backend-quick只编译后端，跳过全仓库 go generate
task build:host本机编译前后端，不启动 Docker
make release-native VERSION=1.2.0本机并行交叉编译，默认 2 个任务、xz -6；RELEASE_GOGIT=1 额外打 Windows Go-Git 包，XZ_LEVEL=9 使用更小但更慢的压缩
task release本机并行交叉编译，不使用 xgo。等价于 make release-native

运行单个测试

Go 测试

# 运行单个测试函数
go test -run '^TestFunctionName$' ./modulepath/...

# 带竞态检测
go test -race -run '^TestFunctionName$' ./modulepath/...

JavaScript/TypeScript 测试

# 运行单个测试文件
pnpm exec vitest path/to/test.spec.ts

# 运行 E2E 测试
GITEA_TEST_E2E_FLAGS='path/to/test.spec.ts' task test:e2e

代码规范

Go

  • 使用 gofmt 格式化
  • 通过 golangci-lint 静态检查
  • 新文件在版权头添加当前年份
  • 无尾随空白

TypeScript

  • 使用 !（非空断言）代替 ?./??（当值确定存在时）
  • 通过 eslint 检查

CSS

  • 优先使用 flex-* 布局辅助类
  • 仅在需要 !important 特异性时使用 tw-* 工具类

Git 提交

  • 使用 Conventional Commits：type(scope): subject
  • Breaking change 在冒号前加 !
  • 测试变更使用 test 类型
  • 提交信息末尾添加 Assisted-by: AGENT_NAME:MODEL_VERSION
  • 不要 force-push、amend 或 squash

发布流程

重要

项目不使用 GitHub Actions。所有格式化、静态检查、测试、竞态检查、镜像验证、跨平台打包和发布验证均在本地完成。

  1. 本地运行 task fmt、task lint:go、task lint:js、task test
  2. 交叉编译并打包 Linux、macOS、Windows 目标
  3. 验证 checksum 和签名
  4. 使用 gh 创建 tag 和发布

不发布增量版本。完成全部需求验证后，创建一个统一的 tag 和发布包。

文档维护

功能、配置、安装、升级、卸载、API、安全、架构或工作流发生变化时，同一变更必须同步更新相关 Markdown 与 docs/site/ HTML 页面。新增页面必须加入 文档首页和侧边导航。

面向自动化协作者的规则、验证步骤或仓库约束变化时，还必须更新 Agent 协作页面与根目录 AGENTS.md。

治理与安全

贡献流程见仓库根目录 CONTRIBUTING.md，安全漏洞按 SECURITY.md 的私密渠道报告，行为准则见 CODE_OF_CONDUCT.md。这些文件描述 Gitsss 当前治理，不使用上游项目的联系人或维护者名单。
